## 五项必要验收的证据

### 1. 终端创建对话，App 自动出现

`scripts/check-terminal-sync.py` 用真正的交互式终端启动系统 pi，发送一条消息并等待回复。`scripts/verify-phase7.ts` 同时开真实 Chrome，确认新对话在 **5 秒内**进入左栏，没有点刷新。单元/集成测试另覆盖真实文件新增、改名、移走及监听失败后的轮询回退。

### 2. 两边打开同一对话，终端写入后阻止 App 继续发送

终端和 Chrome 同时打开同一份对话文件；终端发第二条消息后：

- App 出现黄色提示，发送按钮禁用，Enter 不发送。
- 后台 `assertWritable` 也拒绝写入，不能靠直接发协议绕过按钮。
- 点击“重新载入”后看见终端新消息，黄条消失，草稿仍在。
- 随后 App 真正用 Luna/low 回复，自身写入不会误报成外部修改。

不是用“最近写过”的时间窗口猜测来源。比较完整条目内容，并以真实 `entry_appended` 的 SHA-256 指纹补充当前 runtime 的 `get_entries`。

### 3. 项目文件夹移走，空状态与重新指定

`scripts/verify-phase7-errors.ts` 建立合成项目和会话，再用 macOS `trash` 移走项目目录：

- 5 秒内左栏标出“文件夹已不存在”，点击进入空状态而不是英文报错。
- 重新指定到另一个现有目录后恢复历史；原 JSONL 的首行字节不变，映射只写入隔离的 App 设置。
- `scripts/project-mapping.test.ts` 通过真实系统 pi 的 RPC 执行 `pwd`，确认新工作目录确实生效；再次重新载入也不退回旧目录。
- 鉴权、非法路径、映射循环、不允许给正常项目重新指定等检查通过；读写 App 设置保留其他字段，文件权限为 0600。
- 再移走新目录，从空状态确认整组移到废纸篓；沿用原有的会话校验、忙状态拒绝和 trash 接口。不会直接永久删除。

### 4. 意外退出、断网、错误凭据均为中文

这部分运行**真实 pi 进程和真实 HTTP 请求**，但使用临时配置、合成模型目录及本机隔离服务，不破坏 Kenneth 的真实网络或凭据：

- 测试扩展仅对本次拥有的 pi 进程发送 SIGKILL，App 显示“pi 进程已退出”，点“重新连接”可恢复。
- 隔离服务真正接收到合成错误凭据并返回 HTTP 401，App 显示凭据被拒绝的中文说明；详情展开可见脱敏后的原始 401。
- 隔离服务主动中断连接，真实 pi 报 `Connection error.`，App 显示检查网络/服务后重试的中文说明。
- 不会自动重新发送用户消息。Chrome 未出现未捕获页面错误。

这是对相同失败链路的隔离验收，**不是拔掉机器网络或修改用户真实密钥的测试**。

### 5. 插件提醒默认隐藏、分类隐藏、恢复

隔离测试扩展通过真正的 `ctx.ui.notify` 发两条通知，不向前端伪造通知事件：

- ccstyle 那一类默认不出现，其他 warning 正常出现且有“不再提示这类”。
- 点击后，更换文件路径和数字的同类通知不再出现；刷新页面后仍隐藏。
- 设置里的“已隐藏的提醒”能看到默认项及用户隐藏项；分别恢复后，下一次通知再次出现。
- 指纹包含消息前缀中的插件名，并去掉路径和数字；未标注插件前缀的通知归为“未标明插件”。pi 的 notify 协议没有可靠的独立来源字段，不伪造来源信息。
- 设置读写需后台口令，未知指纹和错误参数被拒绝；恢复默认项与重建设置对象后仍保留选择，项目映射字段不变。

## 验收中修正的问题

- pi 1.4 切会话时先加载新 runtime，再 teardown 旧 runtime；旧插件在 shutdown 追加的条目可能已落盘但不在新 runtime 的 `get_entries`。只看新内存会误报，改为核对真实追加事件的完整指纹。
- 普通 `switch_session` 会重新使用会话头的旧 cwd。采用 App 私有桥接扩展传递 runtime 已支持的 `cwdOverride`，并实测历史、pwd、重新载入和原始头部字节；没有改动系统 pi 安装或对话头部。
- 删除正在展示的失效项目会话后，原目录已不可用；现在回到有效的默认项目，而不是试图在消失的目录里新建。
- 网络故障的真实返回是 `Connection error.`，已纳入中文映射，并保留相应回归断言。
- 第 5 阶段模型曾把“写 hello.sh”的计划测试理解成需要再次问用户是否退出计划模式。测试提示明确先调用 `plan_mode_complete`、等待 Implement here 再实施；仍要求真正出现菜单、点击并创建文件，没有跳过或放宽验收。

## 已知限制与未做

- macOS 第 7 阶段已实测；Windows 本地运行、Codex 下拉/滑杆、插件管理、改动审阅、新安装包均属后续阶段。
