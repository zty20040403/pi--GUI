# 0.1.1：公式渲染与流式频闪修复验收

日期：2026-11-05。范围是修复现有 Mac / 浏览器客户端，不推进 Windows 本地版或后续阶段。

## 问题与修改

### 数学公式

原先仅接入 `remark-math` 的美元分隔符，模型常输出的 `\(...\)`、`\[...\]` 会被 CommonMark 当作反斜杠转义处理。

新增 `src/components/render/remark-latex.ts`，在转义解析之前识别这两种语法，交给现有 KaTeX 排版。不是对整段文本做正则替换，因此不会误改代码围栏、行内代码、链接地址和转义的反斜杠。只处理已经闭合的反斜杠公式；支持中文邻接、上下标、分数、矩阵和跨行公式。聊天与 Markdown 文件预览共用同一条渲染链。

保留 `skipHtml`、KaTeX `trust: false`、宏展开和尺寸限制，数学输入不能生成脚本、危险链接或远程图片。

### 流式更新

原先 `markdownParts()` 在每次渲染时创建新的组件函数。React 会把它们视为新的组件类型，卸载旧的代码块、图片和图表；高亮组件还会在每次文本变化时清空结果。

现在：

- 自定义组件类型固定；目录和文件操作通过稳定的 Context 传递。
- 正文没有变化时，`RichMarkdown` 不再重新解析。首次与后续渲染使用同一套 Markdown 组件，不从简版整块切换为富文本。
- Shiki 输出逐行 React token，保留 `pre`、`code` 和已有行节点；不先清空高亮，也不替换整块 `innerHTML`。
- 超过 200,000 字符或 10,000 行的代码直接使用纯文本，保留完整正文，不产生数万个行组件。
- Markdown 本地图片不因其他回复或计时更新而重新读取。
- Mermaid 新图完成绘制和解码后再替换；输入暂时不完整时保留上一版。SVG 仍经 DOMPurify 处理，只作为 Blob 图片显示。
- 文字和工具增量按动画帧提交到 reducer；后台窗口有 100ms 后备定时器及 256 条队列上限。原始协议事件仍按原顺序广播，结束、错误、停止及切换立即冲刷队列，不丢字、不重排、不过期覆盖最终正文。

这不是冻结整段回复或等全部生成后才显示。新增内容仍然流式出现，已有内容不应被无关更新卸载。

### 回归期间发现的 Mac 启动阻塞

安装副本一度停在“打开对话”，连未授权的健康检查也不返回。对本轮测试后台的系统采样确认，主线程阻塞在 `uv_fs_event_start → open`。

旧代码为检测失效项目，会同步打开并监听所有历史项目的父目录。`SessionSync.watchProjects()` 现改为每 2 秒异步检查**项目本身**的 stat：不进入父目录、不枚举或读取项目文件，不放宽系统权限。仅目录存在性改变时刷新列表，普通内容更新不触发这类刷新。会话目录的实时监听、15 秒漏事件校准、外部改动锁定和重新载入规则不变。

`watchFile` 在目录消失后恢复时可能给出相同的 `previous`，因此独立保存上次存在性，避免漏报恢复。新增测试覆盖移走、恢复、普通文件变化、重复路径、移除监听和关闭清理。

## 固定场景的修复前后对比

以真实 Chrome 执行合成 WebSocket 流式更新；数值是该复现场景的观测，不是帧率基准，也不是“发生了多少次肉眼闪烁”的估算。

| 观测 | 修复前 | 修复后 |
|---|---:|---:|
| 正确显示的样例公式 | 2 / 5 | 5 / 5 |
| 流式反斜杠公式 | 0 / 1 | 1 / 1 |
| 同一张本地图片的读取次数 | 46 | 1 |
| 原历史内容中已脱离页面的观测节点 | 6 | 0 |
| 无关流式更新造成的历史正文 DOM 变更 | 1024 | 0 |

另逐项断言：已有代码块和首行节点仍是原节点、过程中未回退为无高亮状态、复制反馈与链接焦点保留、600 条突发增量顺序正确且最终消息覆盖正确、图表更新保留原图片节点、向上阅读时不抢走滚动位置、万行代码纯文本不丢末行。

观察器仅排除复制按钮自己的计时文案变化。探针必须等第二条 assistant 消息及其真实 `pre` / 首行出现，不能拿历史代码块或空节点冒充正在回复的代码块。

## 没有掩盖的验收问题

- 新数学语法的第一版 lookahead 漏了临时 token 的 enter / exit：生产模式不报错，开发模式触发断言。已修正，并将开发条件下的全部前缀测试加入 `npm test`。
- 旧插件验收写死了 npm 发现页的“最新版本”。现取页面选中的确切版本，确认框、真实 `pi list`、停用配置和卸载结果必须一致，仍是真实隔离安装，不改个人插件。
- 原生菜单测试原先依赖新临时项目自动加载扩展；pi RPC 的项目信任规则会跳过它。现把合成插件放在隔离 agent 目录，模型定义只读链接；先断言命令补全存在，再选中并提交。不改全局信任，不把模型猜测的确认文字当成插件弹窗。
- 流式中尚未写完语言标记的 Mermaid 围栏会暂作为普通代码显示。高亮验收改为定位带唯一标记的 Python 块，最终仍严格检查真实图表和四种公式。
- 安装副本的首次退出超时没有直接算通过；之后再次复现启动阻塞才取得上述采样证据并修复。桌面验收会保留原始错误；失败时断开悬空的 CDP 请求，只按本次随机临时 App 的完整路径清理残留进程，结果仍为失败，不以强制清理冒充正常退出。

## 边界

KaTeX 不等于完整 LaTeX 编译器。代码中的数学源码刻意保持原样；普通段落增行、公式闭合和新图尺寸变化仍可能改变布局高度。没有宣称与 Codex 的内部实现或所有性能指标相同，也没有把自动化当作此次重新完成了所有系统快捷键与 Dock 人工操作。

本次未验证 Safari、Intel Mac 或 Windows 本地客户端。第 11 阶段已有的 Kenneth 人工验收记录保持原有范围，不改写为本次反馈。
